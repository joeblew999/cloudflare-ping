Status: 2026-11-20, written from the user's own words; not started.

The user, 2026-11-20: "at the moment you have to remember a country name and everything … with
void and all the good shit we've got, we can build a really nice filtering GUI that uses the same

## What's wrong now

A place is typed as free text, and you have to know what Globalping accepts:

| Where                            | What you type                | What goes wrong                                                                              |
| -------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------- |
| Probe page and `test --from`     | `TH`                         | Remembering codes; a typo or a place with no probes spends nothing but fails after the click |
| Runs page and `run --from`       | `TH`                         | The same                                                                                     |
| `run --everywhere --at`          | `BKK,SIN`                    | Remembering data centre codes                                                                |
| Map page and `remap --countries` | `TH,SG`                      | The same                                                                                     |
| Coverage                         | nothing: no way to narrow it | 220 KB for an agent that wanted one country                                                  |

## The idea: one thing, a place

A place is somewhere tests can run from, or a list can be narrowed to. Every kind comes from the
lists the app already reads (plan 2026-11-20-03), so every place offered has probes in it:

| Kind            | Example                         | From                                                              | Count on 2026-11-20 |
| --------------- | ------------------------------- | ----------------------------------------------------------------- | ------------------- |
| Continent       | Asia (`AS`)                     | Globalping's probe list                                           | 6                   |
| Region          | South-eastern Asia              | Globalping's probe list                                           | 22                  |
| Country         | Thailand (`TH`)                 | Globalping's probe list                                           | 124                 |
| State (US only) | Virginia (`VA`)                 | Globalping's probe list                                           | 45                  |
| City            | Bangkok, Thailand               | Globalping's probe list                                           | about 1,100         |
| Network         | Cloudflare (`AS13335`)          | Globalping's probe list                                           | about 1,500         |
| Cloud region    | AWS ap-southeast-1              | Globalping's probe tags (AWS, Azure, Google, Oracle)              | 110                 |
| Network type    | home and mobile, or data centre | Globalping's probe tags (`eyeball-network`, `datacenter-network`) | 2                   |
| Data centre     | BKK, Bangkok                    | Cloudflare's list                                                 | 345                 |

Each place has a kind, a name people read ("Thailand", not "TH"; names from the runtime's own
`Intl.DisplayNames`, no data to keep), what's sent to Globalping (its location "magic": `TH`,
`Bangkok+TH`, `AS13335`), how many probes it has, and where it is, for the map.

## One search, everywhere

`places`: given a few letters, the best-matching places, each with its kind and probe count.
Nothing given: the continents and countries, most probes first.

- **API:** `GET /api/places?q=bang&kind=city`. Open, spends no tests, answers from the cache.
- **CLI:** `cloudflare-ping places bang` (and `--json`, as every command).
- **MCP:** the tool `places`, so an agent can find "somewhere in Thailand" before it tests.
- **Pages:** the picker (below) calls the same API as you type.
- Ranking: an exact code first (`TH`, `BKK`, `AS13335`), then names that start with what's
  typed, then names that contain it; more probes first among equals. `bang` gives Bangkok;
  `germ` gives Germany; `virg` gives Virginia (the state), then the Virgin Islands.

## One filter, everywhere

Lists that can be big take the same filter, defined once (a zod schema shared by the commands):
`continent`, `region`, `country`, `state`, `city`, `network`, `datacentre`. Nothing given: the
whole list, as now.

- Coverage first: `GET /api/coverage?country=TH`, `coverage --country TH`, the MCP tool's same
  argument, and `/coverage?country=TH` (a link people can share; Void's ISR keeps each).
- Runs later, by where they ran from, when the list is long enough to need it.

## The picker: one component, every form

`src/PlacePicker.tsx`: a text box that suggests places as you type, from `places`.

- Each suggestion says what it is and what's there: "Thailand · country · 63 probes",
  "Bangkok, Thailand · city · 12 probes", "BKK · Cloudflare data centre".
- Keyboard first: up and down to move, Enter to pick, Escape to close. Built as an ARIA combobox,
  so screen readers say what's offered.
- Without JavaScript it's the plain text box it replaces, so typing `TH` still works.
- One place, or several where the form takes several (the map's countries, everywhere's data
  centres), shown as removable chips.
- Used by: the Probe page's From, the Runs page's From and its everywhere "at", the Map page's
  countries, and the Coverage page's filter.
- On the coverage map, clicking a dot picks its place (later, once the picker is proved).

## Checked before a test is spent

Before a test goes to Globalping, its place is checked against the cached list (no call).
Where nothing matches, the answer says so with the nearest places from the same search ("No
probes in Thialand. Did you mean Thailand?"), instead of Globalping's refusal after the fact.
The CLI and MCP get the same words.

## Build order, each proved before the next

0. **The place index.** Globalping's probe list reduced once into cities (as now, for the
   coverage map) and places (each kind above, with counts), from the one cached read; names from
   `Intl.DisplayNames`. Proof: tests for each kind; counts that match the real list.
1. **`places`, everywhere but the pages.** API, CLI, MCP. Proof: ranking tests (`th`, `bang`,
   `germ`, `virg`, `AS13335`, `BKK`); the real list gives sensible answers.
2. **The picker on the Probe page.** Proof: in the browser, typing and picking with the keyboard
   and the mouse, in light and dark, at phone width; without JavaScript it still sends `TH`; a
   test from a picked city runs.
3. **The picker on the other forms**: Runs (From and everywhere's data centres) and Map
   (countries).
4. **The filter, on coverage**: the shared filter schema; the page, API, CLI and MCP narrowed by
   it; the map showing only what's picked.
5. **Checked before a test is spent**, with suggestions.

## Open, for the build

- The exact magic Globalping takes for a city in a country (`Bangkok+TH`) and a state
  (`Springfield+VA`): checked against its API at step 0, before anything depends on it.
- Whether a network is worth offering by name in the picker, or only by AS number (1,500 names,
  many alike).
- Network type is the one kind that isn't a place, but it narrows where a test runs from in a
  way that matters: home and mobile networks are how real visitors arrive.
- Whether the picker searches in the browser (send the whole index once, about 100 KB) or asks
  the API each time; asking keeps one way in, as everything else does.
